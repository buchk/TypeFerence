# 0028 — Deterministic setup wizard: one generator, browser and CLI

## Status

Accepted. Extends ADR-0010 (browser playground) with authoring tooling;
depends on the v5 closure (ADR-0026, ADR-0027).

## Context

The v5 closure deleted every untyped behavioral channel. The strongest way to
prove that closure livable is to make onboarding run through it: a setup
wizard that assembles a working multilevel `.tfer` suite from a few answers,
compiles it live in the browser, and hands the user the same suite locally.

Two failure modes were designed against:

1. **A second semantics layer.** Implementing scaffolding in playground
   JavaScript creates compiler-adjacent generation logic whose output merely
   happens to be TypeFerence source — guaranteed to drift from `typeference`.
2. **"Same answers, byte-identical" quietly becoming false.** Without
   versioning, reproducibility is only ever "reproducible according to
   whatever init means this month."

Additionally, shell-passed answers (`--norm "text with 'quotes'"`) would put
escaping between the user and determinism; the answer set must travel as data.

## Decision

1. **One generator, two front doors.** A pure Go generator
   (`internal/scaffold`) maps a validated AnswerSet to an in-memory ordered
   `SourceTree` of `{path, bytes}`. The CLI subcommand `typeference init` and
   a new wasm entry point both consume exactly this function. The generator
   knows nothing about browsers, filesystems, tar, or stdout.
2. **Versioned AnswerSet.** Input carries `"schemaVersion"` plus organization,
   norms, team chain, and targets. Parsing uses loader-grade strictness:
   unknown fields are errors. The reproducibility contract is
   **(generator version × AnswerSet schemaVersion) → bytes**, both stamped in
   an emitted scaffold manifest.
3. **Digest reuse, not reinvention.** Scaffold digests are the existing
   `typeference-resource-set-v1` hashing over the generated tree. No parallel
   canonicalization is created.
4. **Golden fixture as acceptance corpus.** One canonical answer set's output
   tree and digest are committed under `conformance/fixtures/`. That fixture
   simultaneously proves typed behavioral context, multilevel composition,
   profile embedding, slot resolution, target emission, compilation,
   deterministic generation, deterministic artifacts, and browser/CLI
   equivalence — because it must compile through the ordinary compiler with
   zero wizard context. A pinned older-schema answer set stays in the corpus
   permanently so future convention changes cannot silently break old answers'
   reproducibility.
5. **Exit ramp by file, not flags.** The wizard offers a download of the tree
   and of `answers.json`, plus the exact command
   `typeference init --answers answers.json --verify <digest>`. `--verify`
   recomputes the digest and fails closed on mismatch, printing which paths
   differ; on a generator-version mismatch it names both versions and the fix
   rather than failing cryptically.
6. **The wizard owns no semantics.** No wizard-only constructs, no hidden
   metadata required to compile, nothing generated that a human could not
   hand-author. This is enforced by the golden fixture compiling without any
   wizard context, not by promise.

Rejected alternatives:

- **JS-side scaffolding in the browser**: second semantics layer; drift.
- **Answers via CLI flags**: shell escaping undermines the determinism story
  for multiline norms and Unicode.
- **A new scaffold digest algorithm**: duplicates canonicalization machinery
  and creates a second thing to keep byte-stable.
- **Deliberate slot collision in the default flow**: pedagogy belongs after
  inheritance lands emotionally; the collision lesson ships as an opt-in
  wizard step instead of in generated defaults.

## Consequences

- Onboarding demonstrates the central claim: typed prose is still ordinary
  prose, just carried by a named type. Users see plain sentences become
  context resources with IDs and digests.
- `typeference init` gives the CLI its first authoring command; every prior
  command assumed an existing source tree.
- The wizard fixture becomes part of CI's determinism gate: any change that
  alters generated bytes fails unless the fixture is regenerated together
  with the version bump that justifies it.
- Playground scope grows past ADR-0010's "no command surface": this ADR is
  the recorded justification. The wizard is authoring tooling over the same
  wasm bridge, not a runtime surface.
